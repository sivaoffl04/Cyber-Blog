# Executive Summary

Modern enterprise Security Operations Centers (SOCs) rely on the **Elastic Stack (ELK)** for centralized log aggregation, real-time alerting, and retrospective threat hunting. Detecting advanced persistent threats (APTs) requires moving beyond basic keyword lookups to behavioral correlation, statistical baselining, and structured query logic using **Kibana Query Language (KQL)** and **Elasticsearch Query DSL**.

This guide accompanies the hands-on video demonstration [`Threat Detection With Elasticsearch And Kibana.mp4`](./Threat%20Detection%20With%20Elasticsearch%20And%20Kibana.mp4) and details the end-to-end workflow for detecting credential stuffing, lateral movement, network anomaly sweeps, and data exfiltration within Kibana.

# Core Threat Hunting & Detection Scenarios

### Scenario 1: Distributed Credential Spraying (MITRE ATT&CK T1110.003)
* **Log Source:** Windows Security Event Log (Event ID 4625 - An account failed to log on)
* **KQL Detection Query:**
  ```text
  winlog.event_id: 4625 and winlog.event_data.SubStatus: "0xC000006A"
  ```
* **Detection Threshold:** High volume of failed logons originating from a single source across multiple distinct target usernames within a short timeframe ($> 20$ events in 5 minutes).

### Scenario 2: Web Application Vulnerability & Path Traversal (MITRE ATT&CK T1190 / T1083)
* **Log Source:** Web Server Access Logs (Apache / Nginx / IIS)
* **KQL Detection Query:**
  ```text
  http.response.status_code: (400 or 403 or 404 or 500) and (url.path: (*..* or *etc*shadow* or *cmd.exe* or *eval\(*))
  ```
* **Analysis:** Isolate sudden spikes in HTTP error codes generated by automated scanners (e.g. Nikto, DirBuster, SQLmap).

### Scenario 3: Anomalous Egress & Data Exfiltration (MITRE ATT&CK T1048)
* **Log Source:** Network Proxy (Squid) & Firewall Telemetry
* **KQL Detection Query:**
  ```text
  network.direction: "egress" and network.bytes: > 50000000 and not destination.ip: (10.0.0.0/8 or 172.16.0.0/12 or 192.168.0.0/16)
  ```
* **Analysis:** Alert on high-volume outbound TCP sessions directed to unclassified public IPs or external dynamic DNS domains.

# 🛠️ Step-by-Step Kibana Threat Hunting Workflow

1. **Index Pattern Selection:** Ensure the correct data stream or index alias (`logs-*`, `winlogbeat-*`, `filebeat-*`) is selected.
2. **Temporal Scoping:** Zoom in on anomaly clusters within the histogram view to isolate burst activity.
3. **Cardinality Analysis:** Construct Kibana **Terms Aggregations** to uncover top talkers, rare user agents, or high-failure destination IPs.
4. **Context Pivot:** Expand individual document records to inspect adjacent logs (`View surrounding documents`) within a $\pm 5$-minute window.

  product: windows

  condition: selection | count() by SourceWorkstation > 25

  - attack.credential_access
