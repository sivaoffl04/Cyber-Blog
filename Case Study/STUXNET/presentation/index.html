🚗 The Infiltration Pathway SUPPLY CHAIN INFECTION

💾 The Anatomy of a Zero-Click USB CVE-2010-2568
  • The Shortcut Trick: Stuxnet dropped weaponized `.lnk` shortcut files onto the flash drive along with hidden loader DLLs (`~WTR4141.tmp`).
  • Windows Shell Parser: `shell32.dll` parsed the shortcut to extract its icon. The icon path was crafted to point to an export inside Stuxnet's DLL.
  • Automatic Code Execution: Windows called `LoadLibraryW()` on the malicious file to render the icon, executing arbitrary Ring-3 code in `explorer.exe` instantly.
  • Air Gap Myth Shattered: Demonstrated that physical air gaps are routinely bridged by humans performing legitimate calibration tasks.

ACT 03 // CRYPTOGRAPHIC EVASION

Subverting Cryptographic Trust

Bypassing 64-bit Windows Driver Signature Enforcement (DSE)
DIGITAL CERTIFICATES // SLIDE 07
🔐 The Driver Signature Enforcement Barrier WHQL SIGNING BYPASS
  • The Security Barrier: 64-bit Windows (x64) enforces strict Driver Signature Enforcement (DSE). Kernel-mode drivers (`.sys`) without a trusted VeriSign/Microsoft signature are blocked from loading.
  • The Intelligence Heist: Rather than attempting to break RSA-2048 cryptography, operators physically or digitally breached two major hardware vendors in Hsinchu Science Park, Taiwan:
    • Realtek Semiconductor Corp.
    • JMicron Technology Corp.
  • Private Key Theft: The attackers exfiltrated the private code-signing keys and signed their malicious rootkit drivers (`mrxnet.sys` and `mrxcls.sys`).
🛡️ Impact on Antivirus & Operating Systems BLIND TRUST
  • Zero Warnings: When Windows installed Stuxnet's kernel driver, it displayed: "Verified Publisher: Realtek Semiconductor Corp."
  • AV Whitelisting: Contemporary antivirus engines routinely whitelisted binaries signed by established global semiconductor manufacturers.
  • Failover Redundancy: When VeriSign revoked Realtek's certificate in July 2010, Stuxnet automatically switched its secondary dropper to use the stolen JMicron certificate!
  • Core Lesson: Trust in digital identity collapses when the private key storage of legitimate vendors is compromised.
ACT 03 // ROOTKIT & STEALTH

Kernel Rootkit & Memory Anti-Forensics

Hooking Native APIs and Hiding Malicious Artifacts in Plain Sight
RING-0 ROOTKIT // SLIDE 08
👻 The `mrxnet.sys` Rootkit Engine SYSTEM CALL HOOKING
  • API Interception: Hooked `NtQueryDirectoryFile` and `ZwQueryDirectoryFile` in the Windows Native API.
  • Ghost Files: When any application (Windows Explorer, Command Prompt, or antivirus scanner) requested a directory listing of the USB drive:
    • Files named `~WTR*.tmp`, `~DF*.tmp`, or malicious `.lnk` files were silently filtered out.
    • The user saw an apparently blank or normal flash drive.
  • Encrypted In-Memory Virtual File System: Stuxnet decrypted its 54 DLL components entirely in RAM. The core payload never touched the hard drive as an unencrypted PE file.
  • Process Injection: Injected code into trusted system hosts (`services.exe`, `lsass.exe`, `explorer.exe`) to execute stealthily.
⏱️ Operational Hygiene & Kill Switches STRICT HYGIENE
  • 3-Hop Infection Limit: Stuxnet tracked an internal propagation counter. A USB drive could only infect up to 3 host machines before self-neutralizing.
  • Hardcoded Expiration Date: Stuxnet contained a built-in kill switch date: June 24, 2012. After this timestamp, the malware ceased all propagation.
  • Target Self-Restraint: If a machine was infected but lacked the specific Siemens software or cascade configuration, Stuxnet remained completely passive.
